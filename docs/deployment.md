# Vercel + Render + GitHub deployment

The project owner selected Vercel for Claude's React/TypeScript frontend, Render for FastAPI and PostgreSQL, and GitHub for source control and automatic deployment. No public URL has been created yet. These integrations were discovered but are not connected at preparation time; no deployment credentials exist in the current environment. Frontend files appeared during concurrent work and remain untouched; its branch/worktree ownership and integration are not yet confirmed. See `frontend-contract-review.md` for observed adapter gaps.

1. Push the reviewed repository including Claude's frontend to GitHub. CI runs SQLite and actual PostgreSQL tests and checks contract drift.
2. Create a Render Blueprint from `render.yaml`. It injects the PostgreSQL private connection string into `DATABASE_URL`, generates an operator key, and prompts for the Vercel origin in `CORS_ORIGINS`. This follows the [Render Blueprint specification](https://render.com/docs/blueprint-spec). The blueprint selects free plans to avoid unapproved charges; account availability and lifecycle limits still need verification before the competition. No paid always-on service has been provisioned.
3. Import the repository into Vercel with root `frontend`, Vite framework, build `npm run build`, output `dist`. Set `VITE_API_BASE_URL` to the Render HTTPS origin, following [Vercel's Vite guidance](https://vercel.com/docs/frameworks/frontend/vite). Never put OpenAI, database or operator secrets in `VITE_` variables or GitHub.
4. Enter the operator key at runtime in the UI (memory only). Deterministic mode runs real backend tools and commits real database changes; it is not a mock-response deployment.
5. Live agent: add `ANTHROPIC_API_KEY` (secret), `ANTHROPIC_MODEL=claude-haiku-5-5` and `FRESHFLOW_LLM_PROVIDER=anthropic` in Render Dashboard → Environment. Never put the key in the frontend or in Git. Without a key the deterministic agent runs, visibly labelled. Live mode never falls back silently. Locally the backend reads `backend/.env` (git-ignored). Usage and cost totals: `GET /api/v1/llm-usage`.

Local development uses SQLite only when `DATABASE_URL` is absent. PostgreSQL row locks and optimistic versions protect concurrent updates. The real PostgreSQL test requires `TEST_DATABASE_URL`, supplied by GitHub CI; it has not run locally. Docker packaging is optional and unverified; Render uses the native Python blueprint.

Read endpoints are public synthetic data. The demo operator key gates costly and state-changing endpoints; production customer use needs individual authentication, authorization, audit identity, rate limits, retention controls and operational monitoring. Add proxy request limits and rate limiting before opening the demo broadly; synchronous simulations are bounded to 100,000 batch-repetitions per request. Provider investigation has bounded calls/timeouts, but no account-wide spend cap in code.

After deployment, verify `/health`, `/docs`, evidence, a small simulation, retrieval after process restart, the T17 flow, wrong-key denial, frontend CORS, and a real live-agent investigation when enabled. Record provider/model, trace, response latency and actual usage costs. Public hosting validation is still required. A public URL must not be reported until the deployed UI and API are tested together.
